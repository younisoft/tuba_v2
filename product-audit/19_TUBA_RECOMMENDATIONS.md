# What Tuba Should Build Better

| Feature | Bayut Implementation | Problems | Recommended Tuba Implementation | Priority |
| --- | --- | --- | --- | --- |
| Dashboard | Static KPI cards and recent listings | Limited explanation and prioritization | Action dashboard with ranked fixes, trends, benchmarks, and next-best actions | P0 |
| Listings | Dense table with lifecycle tabs | Manual scanning, limited bulk intelligence | Saved views, bulk QA, AI quality score, license/media alerts | P0 |
| Post Listing | Simple listing type fork | No visible readiness guidance | Guided wizard with REGA validation, media checklist, autosave, AI description/pricing | P0 |
| TruLeads | Lead table, add lead/task, trend buttons | Weak visible scoring/automation | CRM pipeline with scoring, SLA timers, duplicate merge, WhatsApp/call timeline | P0 |
| Credits | Balance and usage history | No ROI forecast | Credit ROI planner and budget recommendations | P1 |
| Staff | Manage staff page | Permissions unclear | Role templates, audit log, invite/deactivate, team performance | P1 |
| Packages | Package browse page | Static buying experience | Usage-based recommendation and ROI calculator | P1 |
| Reports | Composition + location breakdown + tiered performance time series | Duplicates the dashboard widget; no export, no benchmark, no period comparison | Genuinely additive report builder: period-over-period, market benchmark, scheduled CSV/PDF export | P1 |
| Agent Performance / TruBroker | Leaderboard, TruPoints, 3 locked badges with sub-metrics, team table | Every badge was Locked with no visible "N more to go"; scores computed but not actionable | Same gamification core, but pair every score with a ranked, specific next action; add trend history for TruPoints | P1 |
| Licenses | Single license card + all-or-nothing "Share with agency staff" toggle | Binary sharing, no link from expiry date to affected listings | Per-role license visibility scoping; automatic "listings at risk" panel tied to expiry date | P1 |
| Listing lifecycle (Draft/Removed) | Four distinct non-active states (Not Posted, Insufficient Credits, Ad License Expired, Deleted) across two tabs | No unified glossary; "Insufficient Credits" drafts have no inline top-up path | One status model with plain-language explanations and inline fix actions (top up, renew license, restore) | P0 |

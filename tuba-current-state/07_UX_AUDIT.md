## Cross-cutting UX findings

1. **The platform's real capability regularly exceeds what its UI communicates.** The package-tier grid, the Marketing Requests mechanic, and the sub-user creator-attribution on listings are all genuinely functional, non-trivial features — but each is either buried, unexplained, or under-signaled relative to its actual value. This matches the TBX synthesis's principle #2 ("every status has a next action") extended one step further: several *features*, not just status values, currently have no explanation of what they are or why an agent should care.
2. **The platform's stated activity numbers cannot currently be trusted at a glance.** The Ratings/Reviews tile is confirmedly fake; the notification bell's "0" is suspicious given observed account activity; several inbox rows show impossible sender data (the agent's own identity). An agent evaluating "is this platform working correctly for me" from the dashboard alone would have reasonable grounds for doubt.
3. **Compliance-gating exists but isn't explained.** The Add-Property modal does front-load a licensing step (a genuine strength relative to the "no readiness guidance" framing this assessment initially inferred from source code), but it doesn't explain *why* this step exists, what happens if the agent doesn't have this information yet, or what comes next — a partial implementation of TBX principle #3 ("compliance is a checklist, not a gate") rather than a full one.
4. **Empty and dead-end states are inconsistent in quality** across the platform — from a reasonable "no results" message with an icon (Draft tab) to a genuine dead end with no recovery path (Developer Packages). This inconsistency itself is a finding: there is no shared empty-state pattern being applied platform-wide, consistent with [10_COMPONENT_LIBRARY.md](10_COMPONENT_LIBRARY.md)'s finding that no real component library exists to enforce one.
